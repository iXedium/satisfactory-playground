# Multi-Tab Implementation Plan

## Context

**Approach B: Multiple Instances.** Mount one complete `FactoryPlanner` instance per tab. Each tab gets its own isolated Redux store via a `TabStoreProvider`. Only the active tab is visible (`display: none` on inactive ones). This preserves all existing code with minimal changes.

**Target branch:** `multi-tab` (commit `60280b3`)

**What stays unchanged:** FactoryPlanner internal component tree, all component internals below TreeNode/ItemNode, SummarySidebar, PlannerContent, dataSlice (Dexie game data), Calculator utilities, saveService API client (endpoints unchanged, only call-site names change), dexieInit/dbQueries.

**What is new:** workspaceSlice, TabStoreProvider, FactoryPlannerShell, WorkspaceLayout, TabBar, useWorkspaceSaveLoad.

**What is modified:** historyMiddleware → factory, importExportLogic → factory, store/index.ts → root store, FactoryPlanner → accepts tabId/isActive props, all hooks → accept tabId, localStorage keys → namespaced, context providers → re-parented, usePlannerSaveLoad → activeSetupName to localStorage.

---

## Final Component Hierarchy

```
main.tsx
└── Root Provider (workspaceSlice + dataSlice)
    └── InitializationProvider
        └── App.tsx
            └── WorkspaceLayout
                ├── TabBar                  (reads workspaceSlice + dirtyMap)
                └── [per tab, all mounted]
                    └── TabStoreProvider    (own Redux store per tab)
                        └── HideToggleDragProvider
                            └── TreeNavigationProvider
                                └── FactoryPlannerShell (forwardRef)
                                    props: tabId, isActive,
                                           initialState?, onDirtyChange
                                    ref: { getFullState() }
                                    └── FactoryPlanner
                                        props: tabId, isActive
```

## Implementation Steps

### Step 1 — Factory-ize module-level state

**Implementation:**
- Convert `historyMiddleware` (single export) → `createHistoryMiddleware()` factory that returns a new closure. The `activeTransaction` variable moves inside the closure, scoped per store instance.
- Convert `nodeRecipeCache` in `importExportLogic.ts` → accept a `Map<string, Recipe>` as a parameter, eliminating the module-level singleton. Export `createImportLogic(cache: Map)`.
- No other behavior changes.

**Tests:**
- Call `createHistoryMiddleware()` twice → mwA, mwB
- Configure two minimal stores using `configureStore` with mwA and mwB
- Begin history transaction via storeA's dispatch
- Assert storeA activeTransaction is not null, storeB activeTransaction is still null
- `createImportLogic(mapA)` and `createImportLogic(mapB)`: trigger recipe lookup via logicA, assert mapA has entry, mapB is empty
- TypeScript compilation: zero errors

### Step 2 — Store split

**Implementation:**
- `store/index.ts` becomes ROOT store: holds `workspaceSlice` + `dataSlice` only. Removes `dependencies`, `recipeSelections`, `treeUi`, `comparison`, `history` slices and `historyMiddleware`.
- Export `RootState` and `AppDispatch` from root store.
- New file `src/store/plannerStore.ts`:
  - Export `createPlannerStore()` factory calling `configureStore` with planner slices (`dependencies`, `recipeSelections`, `treeUi`, `comparison`, `history`) + `createHistoryMiddleware()`.
   - Export `PlannerRootState = ReturnType<ReturnType<typeof createPlannerStore>['getState']>`
   - Export `PlannerAppDispatch = ReturnType<typeof createPlannerStore>['dispatch']`
- New file `src/store/workspaceSlice.ts`:
  - Actions: `addTab`, `removeTab`, `setActiveTab`, `renameTab`, `reorderTabs`
  - State: `{ tabs: { tabId: string, name: string }[], activeTabId: string | null }`
  - Persisted to localStorage key `workspaceState`
  - Initializes with one default tab if `tabs.length === 0`
- Update ALL planner file imports: `RootState` → `PlannerRootState`, `AppDispatch` → `PlannerAppDispatch`, import paths from `../../store` → `../../store/plannerStore` (and equivalent relative paths for hooks/components).
- Fix `ImportExport.test.js` for any store import breakage.

**Tests:**
- `workspaceSlice`: test addTab, removeTab, setActiveTab, renameTab, reorderTabs with standard Redux slice tests
- Assert root `RootState` shape does NOT include dependencies/recipeSelections/treeUi/comparison/history
- Assert `PlannerRootState` shape does NOT include workspaceSlice
- `createPlannerStore()`: call twice, assert two independent store instances
- TypeScript compilation: zero errors
- `ImportExport.test.js` passes

### Step 3 — tabId threading + localStorage namespacing

**Implementation:**
- Add `tabId: string` and `isActive: boolean` props to `FactoryPlanner` component.
- Thread `tabId` through `useFactoryPlanner(tabId, isActive)` → all sub-hooks.
- Each hook that reads/writes localStorage: prefix keys with `lastSession_{tabId}_`. Create helper `getNamespacedKey(baseKey: string, tabId: string): string`.
- Hook-by-hook key changes:
  - `usePlannerNodeState`: 5 keys (`lastSession_tab-{id}_savedExcessMap`, etc.)
  - `usePlannerDisplayOptions`: 7 keys
  - `useFactoryPlanner`: 5 keys (including `plannerManualTreeOrder_{tabId}`)
  - `FactoryPlanner.tsx`: `plannerSummaryVisible_{tabId}`
  - **`usePlannerItemSelection`: `lastSession_savedRecentItems` — GLOBAL ONLY. This hook manages exactly one localStorage key and it is intentionally NOT namespaced. Recent items are user-level UX convenience, not per-tab planner state. Do NOT prefix this key; it must remain readable and writable across all tabs.**
  - `usePlannerSaveLoad`: `activeSetupName_{tabId}` — namespaced (see Step 8)
- `FactoryPlanner` receives `tabId` and passes it down.
- Verify single-tab mode still works end-to-end.

**Tests:**
- `getNamespacedKey('savedExcessMap', 'tab-A') === 'lastSession_tab-A_savedExcessMap'`
- Spot-check 3 keys: `savedExcessMap` (NodeState), one key from DisplayOptions, `plannerManualTreeOrder` (FactoryPlanner)
- For each: render FactoryPlanner with `tabId='tab-A'`, trigger state change, assert namespaced key written, assert un-namespaced key NOT written
- Assert `lastSession_savedRecentItems` is NOT namespaced
- `jest.useFakeTimers()` + `jest.advanceTimersByTime(500)` for debounced saves
- TypeScript compilation: zero errors
- Visual: load app, load 'tier-1' setup, screenshot → `TEMP_SCREENSHOTS/step3-single-tab-tier1.png`, verify no regressions

### Steps 4+5+6 (merged) — Shell, providers, store provider

**Implementation:**
- Move `HideToggleDragProvider` and `TreeNavigationProvider` from `App.tsx` level INTO each tab boundary (inside `TabStoreProvider`, wrapping `FactoryPlannerShell`).
- Create `FactoryPlannerShell` (new component, `forwardRef`):
  - Props: `tabId`, `isActive`, `initialState?: SavedPlannerState`, `onDirtyChange?: (dirty: boolean) => void`
  - Ref: `useImperativeHandle` exposing `{ getFullState(): SavedPlannerState }`
  - If `initialState` is provided, skip all localStorage auto-load effects (pass `skipLocalStorageLoad` flag through hooks)
  - Calls `onDirtyChange` effect whenever `isDirty` from `usePlannerSaveLoad` changes
  - Renders `FactoryPlanner` with `tabId` and `isActive` props
- Create `TabStoreProvider`:
  - Maintains module-level `Map<tabId, Store>` cache
  - On mount, creates or reuses a planner store via `createPlannerStore()`
  - On unmount (cleanup effect), deletes `plannerStores.delete(tabId)`
  - Wraps children in `<Provider store={plannerStore}>` then `HideToggleDragProvider` then `TreeNavigationProvider`

**Tests (unit only, no render tests):**
- Store cache: mount with `tabId='tab-X'`, capture store ref; mount again same tabId, assert same instance; unmount, assert cache cleared; mount again, assert NEW instance
- Cross-tab isolation: mount TabStoreProvider A and B; dispatch to store A; assert store B's dependencyTrees is empty, store A's has the data
- Shell ref: mock `useFactoryPlanner`; assert `ref.current.getFullState()` returns valid `SavedPlannerState` shape
- Shell initialState: provide mock `initialState`; assert `localStorage.getItem` is never called
- Shell onDirtyChange: `jest.useFakeTimers()` + `advanceTimersByTime(500)`; assert callback fires with correct boolean
- TypeScript compilation: zero errors

### Step 7 — WorkspaceLayout + TabBar + multi-tab rendering

**Implementation:**
- Create `WorkspaceLayout`: reads `workspaceSlice` for tab list + activeTabId. Renders `TabBar` + all tab instances. Each tab wraps: `TabStoreProvider` → `FactoryPlannerShell`. Inactive tabs get `style={{ display: 'none' }}`.
- Create `TabBar`: renders tab strip with tab names, add-tab button, close-tab button. Inline rename (double-click to edit). Shows dirty indicator (dot) on tabs where `dirtyMap[tabId]` is true. Shows warning at 10+ tabs. **Tab drag-to-reorder is explicitly deferred** — the `reorderTabs` action exists in `workspaceSlice` but drag-and-drop tab reordering in the TabBar UI is out of scope for this plan.
- Wire `isActive` from `WorkspaceLayout` to each `FactoryPlannerShell`, which passes it to `useFactoryPlanner` → `useUndoRedo(enableKeyboardShortcuts: isActive)`.
- Wire `onDirtyChange` from each `FactoryPlannerShell` to `WorkspaceLayout` → updates `dirtyMap` → `TabBar` reads it.
- On tab deletion: dispatch `removeTab` → cleanup effect clears all `lastSession_{tabId}_*` localStorage keys and removes from store cache.

### Step 8 — Per-tab save name prefixing

**Implementation:**
- In `usePlannerSaveLoad`: when calling `saveService.save(name)`, prefix name with `tab:{tabId}:` → `saveService.save('tab:{tabId}:' + name)`
- In `getSaveNames()`: filter saves by `tab:{tabId}:` prefix, strip prefix before returning to UI
- **Move `activeSetupName` from server API to per-tab localStorage:** Replace `saveService.getActiveName()` and `saveService.setActiveName()` calls with `localStorage.getItem('activeSetupName_{tabId}')` / `localStorage.setItem('activeSetupName_{tabId}', name)`. The server `/api/saves/active` endpoint is no longer called by `usePlannerSaveLoad`.
- On initial mount: read active name from localStorage. On save: write active name to localStorage. On delete: if the deleted setup was active, clear localStorage key.
- `saveService.getActiveName/setActiveName` endpoints remain in `saveService.ts` (unchanged) but are no longer consumed.

### Step 9 — Workspace save/load

**Implementation:**
- Create `useWorkspaceSaveLoad` hook (workspace-level, used in `WorkspaceLayout`):
  - `saveWorkspace(name)`: iterates all tab refs via `getFullState()`, gathers per-tab state, bundles with tab metadata, saves as `'workspace:' + name` via `saveService`
  - `loadWorkspace(name)`: fetches state from `saveService`, dispatches `setWorkspaceTabs` to populate `workspaceSlice`, passes `initialState` prop to each `FactoryPlannerShell`
  - Serialized format: `{ version: 1, tabs: [{ tabId, name, plannerState: SavedPlannerState }], activeTabIndex: number }`
- Workspace save UI: save button in `TabBar` or workspace-level menu

**Tests:**

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `historyMiddleware` module-level state shared across tabs | Factory pattern creates independent closures per store (Step 1) |
| `nodeRecipeCache` cross-tab corruption | Map parameter passed per factory instance (Step 1) |
| `useUndoRedo` global keyboard listener fires on all tabs | `isActive` prop disables keyboard shortcuts on inactive tabs (Step 7) |
| Workspace load timing race with auto-load effects | `initialState` prop suppresses localStorage auto-load via `skipLocalStorageLoad` flag (Step 5) |
| Store cache memory leak on tab deletion | `TabStoreProvider` cleanup effect deletes from Map (Step 6) |
| Save name collisions across tabs | `tab:{tabId}:` prefix namespacing on server, stripped for UI display (Step 8) |
| `AppDispatch` type confusion after store split | Export separate `PlannerAppDispatch` from `plannerStore.ts`; update all imports (Step 2) |
| `ImportExport.test.js` breakage | Update store imports; verify passes in Step 2 |

## Open Questions (Resolved)

1. **Tab dirty indicator** — Included via `onDirtyChange` callback on `FactoryPlannerShell`
2. **activeSetupName** — Moved from server API to per-tab localStorage
3. **Context providers** — `HideToggleDragProvider` + `TreeNavigationProvider` moved inside each tab's `TabStoreProvider`
4. **Workspace save/load** — Save via ref-based `getFullState()`, load via `initialState` prop
5. **Undo/redo scoping** — `useUndoRedo(enableKeyboardShortcuts: isActive)` gates global listener
6. **Default tab on first launch** — `workspaceSlice` seeds one default tab when `tabs.length === 0`

## Deferred

- **Tab drag-to-reorder in TabBar:** The `workspaceSlice.reorderTabs` action exists and is tested, but the TabBar UI does not include drag-and-drop reordering. Tabs appear in creation order. This is deferred to a future iteration.
- **Tab count >10 UX:** Only a warning is shown; no hard enforcement.
